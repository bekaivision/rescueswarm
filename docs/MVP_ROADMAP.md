# RescueSwarm: итоги Фаз 0–6 и путь к MVP

Состояние на 2026-11-13. Это предложение для обсуждения, `docs/PLAN.md` не менялся.

## 1. Итоги

Смешанный рой (наземные роботы и дроны) в симуляции строит общую карту разрушенного
здания и ищет людей. Фазы 0–6 сделаны за 7 дней (2026-11-07…13), всё в `main`.

| Фаза | Что сделано | Главные цифры (seed 1, 2, 3, 7) |
| --- | --- | --- |
| 0 | Docker-стенд, Gazebo с окном и без | RTF 0.985, VRAM 153 / 451 MiB |
| 1 | 3 наземных робота, сенсоры, Nav2 | RTF 1.0, частоты сенсоров в норме |
| 2 | Самостоятельное исследование: границы и аукцион целей | покрытие 95–96%, t90 246–334 с |
| 3 / 3b | Поиск людей: тепловизор, YOLO по RGB, осмотр кандидатов | найдено 19 из 19 доступных, 0 ловушек, 1–3 «призрака» |
| 4 | Поза от `mrg_slam` вместо истинной | ATE 0.26 м, люди 19/19, точность карты P@2 0.698 при пороге 0.7 (единственный FAIL) |
| 5 | Дроны: простая модель и PX4 SITL, двухслойная карта | последний человек найден за 96 с против 328 с у наземных, сдвиг слоёв 0.05–0.10 м |
| 6 | Связь через `comms_sim`: 4 уровня и обрывы | 19/19 на всех уровнях; при `poor` миссия 618 с вместо 158 с; после обрыва база догоняет за 2 с |

Код и инфраструктура:

- 10 пакетов ROS 2, около 19 тыс. строк вместе со скриптами. `make test`: 260 тестов, все
  проходят (проверено 2026-11-13).
- Всё собирается в Docker, зависимости закреплены по хэшам. Образ около 13 GB (PX4 и torch).
- Видео есть для всех фаз 0–6 (`media/`), посты LinkedIn есть до Фазы 5.
- `results/` (2.1 GB) и `media/` (150 MB) не в git: результаты и видео есть только на этом диске.

Главный вывод на сегодня: смешанный рой находит всех людей примерно в 3 раза быстрее
наземного, и связь уровня `medium` почти не мешает. Вывод пока предварительный, см. ниже.

## 2. Чего не хватает до MVP

1. **Нет полной связки.** SLAM (Ф4), дроны (Ф5) и связь (Ф6) ни разу не работали вместе.
   В Ф5–6 наземные роботы ездят на истинной позе. Данные `mrg_slam` через `comms_sim`
   не проводились (риск из PLAN §10 открыт).
2. **Нет статистики.** Один прогон на seed, а разброс большой: P@2 в Ф4 между повторами
   0.67–0.82. Все пороги подбирались на тех же seed 1, 2, 3, 7, проверки на новых мирах нет.
3. **Вопросы исследования.** RQ1 (состав роя) и RQ4 (3–5 роботов) не отвечены. RQ3
   (совмещение карт) отвечен формально: общая система координат и идеальный GPS.
4. **Нет «лица» для пользователя.** Результат сейчас: топики ROS, RViz и `people.json`.
   Нет экрана оператора и отчёта о миссии.
5. **Опора на истину.** Стартовые позы, границы карты и стены берутся из
   `ground_truth.yaml`. Лёгкие дроны летают на истинной позе. Лидар и GPS идеальные.
   Loop closures в `mrg_slam` выключены.
6. **Воспроизводимость для чужого человека.** Нет LICENSE, CI и `make demo`. В README нет
   `make deps` и требований к железу. Патч `mrg_slam` лежит в `patches/`, но не
   применяется. compose всегда требует NVIDIA.
7. **Устаревшие замеры.** Нагрузка (Ф0–2) снята до восприятия, SLAM, дронов и связи.
   `phase-3.mp4` снят до последнего исправления Ф3b.
8. **Мелкие долги.**
   - Список `ground_1..3` по умолчанию прописан примерно в 10 узлах: при N=4–5 узел без
     параметра тихо работает с тремя роботами.
   - `generate.py` поддерживает не больше 3 дронов.
   - `make check-phase5` не передаёт `MODES`.
   - `check_phase6.sh` всегда запускает дронов: наземный рой при плохой связи не проверен.
   - Остатки `scripts/phase2_dev/`, неописанные скрипты `yolo_*` и `slam_*`.

## 3. Предлагаемое определение MVP

**MVP = демо-продукт в симуляции**, который можно показать партнёру или заказчику и
повторить на другой машине:

1. Одна команда `make demo` поднимает полную связку: 3 наземных робота на SLAM, 2 дрона,
   связь `medium`, новый случайный мир.
2. Оператор в браузере видит живую карту, роботов, состояние связи и отметки людей.
3. В конце миссии сам собирается отчёт (HTML): карта с людьми, таблица людей (координаты,
   уверенность, время, кто нашёл), кривая покрытия, статистика связи.
4. Цифры подтверждены сериями: RQ1–RQ4 со средним и разбросом, включая новые seed.
5. Репозиторий готов к показу: LICENSE, README на английском, CI с тестами, видео,
   технический отчёт.

Не входит: реальное железо, свой закрытый GUI, больше 5 роботов, полный отказ от опоры на
истину.

## 4. План

Каждая фаза ведётся в отдельной сессии, коммит в конце. При нынешнем темпе весь путь
займёт 1.5–2.5 недели.

### Фаза 7a. Порядок и полная связка (1–2 дня)

**Сделано 2026-11-13, коммит `9fb0059`, отчёт [PHASE_7A_REPORT.md](PHASE_7A_REPORT.md).**
Патч `mrg_slam` оказался хуже и не применяется. Полная связка медленная: RTF 0.4–0.65.

- [ ] Мелочи: `MODES` в Makefile, `make deps` в README, список роботов из одного места
  (launch) без тихого отката к трём.
- [ ] Патч `mrg_slam`: сравнить с ним и без него на 4 seed. Если не хуже, применять
  автоматически в `make deps`.
- [ ] Проверить запуск N=4 и N=5, с дронами и без.
- [ ] Полная связка `LOC=slam DRONES=2 COMMS=medium` на 4 seed, сначала light, потом px4.
  Убедиться, что `mrg_slam` не обменивается данными между роботами в обход `comms_sim`,
  иначе выключить этот обмен.
- [ ] Открытые пункты восприятия: вторая отметка на том же теле; перепроверка CONFIRMED,
  если высота потом выросла выше 0.4 м; потеря person_6 на seed 2 из-за `body_merge`.

**Готово, когда:** полная связка проходит на 4 seed (найдено не меньше 18 из 19 доступных
людей, 0 ловушек, не больше одного «призрака» на прогон), N=5 запускается, `make test`
зелёный.

### Фаза 7b. Серии экспериментов (= Фаза 7 в PLAN.md, 2–4 дня, в основном машинное время)

- [ ] `make eval`: запуск по матрице из YAML (сценарий × seed × повтор), продолжение после
  сбоя, сторож низкого RTF (в PX4 был прогон с RTF 0.01), проверка GPU перед каждым
  прогоном. Сводка в `results/phase-7/summary.md`, CSV и графики (среднее и разброс).
- [ ] Новые seed (например, 11–18) для честной проверки.
- [ ] RQ1: только наземные, смешанный, только дроны. Дроны людей не подтверждают, поэтому
  для них считаем кандидатов рядом с людьми.
- [ ] RQ4: 3, 4 и 5 роботов. Новые замеры RTF, CPU, RAM, VRAM на финальном стеке.
- [ ] RQ2: добавить наземный рой при `good` и `poor`.
- [ ] RQ3 (по желанию): шум и смещение GPS у дронов, как от них меняется сдвиг слоёв.

Бюджет: 150–250 прогонов по 5–15 мин, это 1–2 ночи. Матрицу можно урезать. Серии
запускать фоновой командой, не через субагентов. Фазу можно вести на Sonnet: в ней в
основном скрипты и ожидание.

**Готово, когда:** `make eval` повторяет все таблицы, RQ1–RQ4 отвечены со средним и
разбросом, есть результаты на новых seed.

### Фаза 7c. Экран оператора и отчёт миссии (2–3 дня)

- [ ] `foxglove_bridge` в образе и готовая раскладка для Foxglove или его открытого форка
  Lichtblick: карта, роботы и их пути, отметки людей со статусом, состояние связи.
- [ ] Отчёт миссии `mission_report.html` в конце каждого прогона: из `people.json`,
  карты, `coverage.csv` и статистики связи. Список людей ещё и в CSV.
- [ ] `docs/API.md`: что база отдаёт наружу (топики и схема `people.json`). Это граница
  для будущего закрытого GUI, она важна из-за AGPL у YOLO.
- [ ] `make demo`: полная связка, экран оператора и отчёт одной командой.

**Готово, когда:** `make demo` на чистом клоне даёт живую картинку и отчёт; снято
демо-видео на 30–60 с.

### Фаза 8. Упаковка и публикация (= Фаза 8 в PLAN.md, 2–3 дня)

- [ ] Решения владельца: название, лицензия (предложена AGPL-3.0), публичный репозиторий
  или нет.
- [ ] README на английском: что это, требования (NVIDIA GPU, Docker, место на диске, время
  сборки), быстрый старт, демо, таблица результатов, ограничения.
- [ ] CI в GitHub Actions: юнит-тесты в лёгком образе ROS без GPU и PX4. Тяжёлый образ в
  CI не собирать.
- [ ] Вариант compose без NVIDIA (без окна и без RGB) для машин без GPU.
- [ ] Итоговые таблицы и графики в git (`docs/results/`); видео в GitHub Releases или на
  сайте.
- [ ] Технический отчёт (сводка семи отчётов фаз, на английском и русском) с честными
  ограничениями. Итоговый ролик, карточка на bekaivision.github.io, посты LinkedIn за Ф6–7.
- [ ] Уборка `results/` (`phase-4/diag` 1.6 GB, в основном `.mcap`; прерванные каталоги
  Ф5), только после подтверждения владельца.

## 5. После MVP

| Направление | Зачем | Сложность |
| --- | --- | --- |
| Убрать опору на истину: неизвестные стартовые позы, совмещение карт между роботами, loop closures или Swarm-SLAM через связь | главный научный шаг, честно закрывает RQ3 | высокая |
| Реалистичные сенсоры: шум лидара и тепловизора, дроны без GPS, отличие тёплого мусора от человека сверху, дообучение YOLO для 6–8 м | меньше разрыв с реальностью | средняя |
| Сценарии миссии: батарея и возврат, отказ робота, приоритетные зоны от оператора | ближе к продукту | средняя |
| Закрытый GUI спасателя (отдельный проект через API) | нужен для продаж | средняя |
| Один реальный робот и тепловизор | первый замер разрыва sim-to-real | высокая |
| 10–15 роботов на сервере | только если понадобится исследованию | средняя |
