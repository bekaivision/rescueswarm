прогрева, скрипт `scripts/bench_phase0.sh headless|gui`.

Состояние хоста: идёт обычная работа (браузер, приложение Claude), средняя нагрузка
около 2, `top` показывает около 93% простоя CPU; GPU до запуска 15 MiB. Запись `idle.txt`
лежит рядом с каждым замером. Измерения не получены на полностью простаивающей машине.

Замечания:
- В каждом прогоне по одному отсчёту RTF резко упало (0.46 и 0.47) на секунды сразу
  после подключения подписчиков. Причину не выясняли, остальные отсчёты около 1.00.
  Первый отсчёт каждого прогона (устаревшее сообщение) отбрасывается скриптом, сырые
  данные сохранены в `rtf.txt`.
- Сенсоры Gazebo рендерят кадры только при наличии подписчика. Скрипт подписывается на
  `/camera` и `/lidar`, поэтому нагрузка включает рендер сенсоров. Без подписчиков нагрузка
  меньше.
- `docker stats` считает CPU в процентах от одного ядра, в таблице пересчитано в ядра.

## Отклонения от черновиков плана

- `ros-dev-tools` добавлен: в `ros:jazzy-ros-base` нет `colcon`. Добавлены также
  `x11-utils`, `x11-apps` (xwininfo, xwd), `fonts-dejavu-core`, `procps`, `libglvnd0`,
  `libglx0`, `libgles2`, `libgl1-mesa-dri`, `git`, `sudo`.
- В базовом образе уже есть пользователь `ubuntu` с UID 1000, из-за чего `useradd -u 1000`
  падает. Он удаляется перед созданием `dev`.
- Каталог `/home/dev/.gz` создаётся в образе с владельцем `dev`, иначе именованный том
  `gz-cache` принадлежал бы root. `HOST_UID` и `HOST_GID` передаются из `id -u/-g`.
- `${XAUTHORITY}` в compose заменён на `${XAUTHORITY:-$HOME/.Xauthority}`. Добавлены
  `name: rescueswarm`, `__VK_LAYER_NV_optimus=NVIDIA_only`, `working_dir`.
- `ENTRYPOINT ["/ros_entrypoint.sh"]` подключает ROS, поэтому `gz` в PATH и в `make shell`;
  в `~/.bashrc` пользователя `dev` добавлен `source` ROS и workspace.
- Пустой `deps.repos` имеет вид `repositories: {}`; `vcs import` его принимает.
- `make eval` пока заглушка (код 1). `make video PHASE=0` собирает видео, для других фаз код 1.
  `make sim-headless` по умолчанию запускает `phase0_bench.sdf` (переменная `HWORLD`).
- Добавлены `NOCACHE=1` для `make image` и `RUNFLAGS=-T` (запуск без TTY).

## Ограничения

- Накладные расходы Docker измерить нельзя: нативный Jazzy на Ubuntu 22.04 не
  устанавливается, базовой линии нет. Измерены абсолютные показатели в контейнере
  (RTF около 1.0 на простой сцене). Разницу Docker и нативной установки не оценивали.
- Простая сцена: физика без роботов, одна камера и один лидар. Нагрузка роя (Фаза 1+) будет
  выше, RTF при 3 и 5 роботах нужно мерить отдельно.
- `libEGL warning: egl: failed to create dri2 screen` в логах headless: Mesa пробует
  AMD/DRI и откатывается; рендер идёт на NVIDIA (процесс виден в `nvidia-smi`). На работу
  не влияет. Отдельно `__VK_LAYER_NV_optimus` не проверялся: Gazebo здесь использует OpenGL
  (ogre2).
- Окно GUI захватывалось `xwd -id` (содержимое самого окна), других окон рабочего стола
  в снимке нет.
- Проверка `make build` и `make test` на пустом workspace: оба возвращают
  код 0 (`make_targets.log`). Это не проверка работы с реальными пакетами.

## Видео

Файл `media/phase-0.mp4` (не в git), 20.5 с, H.264 yuv420p, 1080x1080, 30 к/с, без звука,
подписи вшиты (DejaVu Sans). Сборка: `make video PHASE=0` (кадры уже есть, пересъёмка:
`scripts/video/phase0.sh --rerecord`). Всё идёт в Docker.

| Время | Шот |
| --- | --- |
| 0-4 с | Настоящая съёмка Gazebo: тела падают и катятся (мир `configs/worlds/phase0_video.sdf`), подпись «Gazebo Harmonic in Docker» |
| 4-10 с | Карточка терминала: `make sim` и строки из `glxinfo -B` (renderer RTX 3060 Laptop GPU) и `nvidia-smi` (`gz sim gui` 272 MiB); значения из этого отчёта и `results/phase-0/` |
| 10-17 с | Продолжение той же съёмки, подпись с замерами из отчёта: RTF 0.99, VRAM 153 MiB, камера 30.2 Гц (headless) |
| 17-20.5 с | Логотип Bekai Vision, «RescueSwarm | Phase 0» |

Во всех кадрах кроме логотипа есть метка «Simulation». Съёмка: Gazebo без окна
(`--headless-rendering`) на NVIDIA, камера 1080x810 при 30 Гц пишет PNG по тегу `<save>`;
скорость видео задаётся временем симуляции (330 кадров = 11 с), а не производительностью
ноутбука. Окно GUI не снималось (чтобы в кадр не попал рабочий стол). Строки терминала на
карточке набраны текстом по реальным логам, команды `glxinfo` и `nvidia-smi` в ролике не
запускаются заново; из строки renderer убраны слово `string` и суффикс `/PCIe/SSE2`.
Камера ролика 1080x810, а не 640x480 из замера: числа RTF и VRAM относятся к сцене замера.

```bash
make sim-headless               # без окна

scripts/bench_phase0.sh gui 60
make video PHASE=0              # media/phase-0.mp4
```
